GPUIX is a framework for building GPU-rendered native desktop applications using React, Solid or Lua. It uses GPUI, Zed’s rendering framework, rather than a browser or web view. We need a design for its built-in developer inspector and a small visual foundation that can also be reused across our other developer tools.

The inspector opens inside the application being inspected. A developer right-clicks an application element and chooses Inspect element, which opens a dock at the bottom of that window. The application remains visible and interactive above the dock. The inspector should feel like an integrated native development tool, not a separate website or dashboard.

The dock needs a compact toolbar with a title, an element-picker toggle and a close button. Below it, an expandable element tree sits beside a properties pane. A draggable divider should resize the two panes, and a draggable top edge should resize the dock. The design should show these controls and explain their interaction states, even though resizing is not implemented yet.

The element tree shows retained host elements, not framework components. Rows may contain an element name, a numeric ID, an optional test label and a short text preview. The design should accommodate long labels, deeply nested trees and enough rows to require scrolling. Hover, keyboard focus and selection must be visually distinct. Selected rows should be easy to follow without overwhelming the hierarchy or its indentation guides.

The properties pane should present declared styles, custom properties, registered event names and last-painted bounds in readable sections. It currently displays raw JSON, which we want to replace with a structured, scannable presentation. Please account for long values, nested data, empty sections, elements with no available painted bounds and selections that disappear when the application updates. Some styling values are declarations rather than computed layout values, so the presentation should not imply that every value is a computed result.

We also need a small context menu containing Inspect element and an unobtrusive outline around the selected element in the running application. Element-picking mode should be clearly active and easy to cancel. While picking, clicking the application selects an element without activating its normal behaviour. Inspector interactions should preserve application state.

The visual direction is restrained native tooling with the information density of developer tools. Zed is a useful reference for compactness and integration, while Chrome DevTools is a useful reference for inspection workflows. Avoid oversized dashboard cards, excessive whitespace and decorative effects. Prioritise clear hierarchy, readable small text, precise alignment and discoverable controls. Start with a dark theme, but choose semantic colour roles that can support a light theme later. The project already supports Phosphor icons, so use those rather than introducing another icon family.

Alongside the inspector, propose a small reusable design foundation covering semantic colours, typography, spacing, corner radii and control sizes. Show how these choices apply to buttons, icon buttons, menus, tree rows, section headers, property rows and dividers. Include consistent hover, pressed, selected, focused and disabled states. This foundation should style our own tooling and be optionally reusable by applications; it should not force every GPUIX application to look the same.

The implementation uses native GPUI layout and painting. Standard flex layouts, text, SVG icons, borders and simple backgrounds translate well. Avoid relying on browser-specific CSS effects. The inspector itself is implemented in Rust, while application components can be implemented in Lua or TypeScript, so a shared visual specification is more useful than a design tied to one frontend framework.

Please provide an annotated mockup of the inspector inside a running desktop application, examples of its important interaction and empty states, an explanation of resizing behaviour and a compact specification of the visual tokens and reusable component states. Keep the scope focused on read-only inspection. Style editing, source navigation, framework hooks and performance profiling are not implemented and should not be central to this design.
